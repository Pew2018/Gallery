## 1. 为什么调整方案

用户要求：不希望继续无止境地给刷新、索引、滚动与动画问题打补丁；也**不希望为了这些问题重造整个相册**。倾向保留 Fossify Gallery 原有成熟底层，只整理因为自定义照片配置等新增功能而变复杂的扫描、排序和显示链路，使用**尽可能小的工程量**减少回归问题。

原先 01–04 是静态源码事实、风险目录与全面重构的参考文档，**不是现阶段必须实施的 V2 任务清单**。当前优先尝试小规模结构整理，只有实证证明小修无法可靠收敛时才扩大范围，且需记录理由。

## 2. 唯一核心目标

**在不改变用户侧主要功能和数据格式的前提下，让扫描结果准确、排序顺序稳定、界面提交可预测；减少重复扫描、过期回调、无意义列表重排、加载长期不结束和全屏浏览顺序不一致。**

强调三项职责：扫描回答“有哪些、读取是否完整、是否仍有授权”；排序回答“相同范围与设定下的权威展示顺序”；显示回答“如何最少量更新已经可见的列表”，三者不擅自替另一层决定状态。

本阶段不追求引入全新数据库索引、统一全部 Activity 生命周期或重建媒体解码器。

## 3. 必做工作（最小改动优先）

### S1：扫描调度和结果边界（保留实际文件读取器）

- 保留 `MediaFetcher`、`FolderFileAccess`、MediaStore/文件系统/SAF 读取以及 `.nomedia` 路径，不重新实现存储模型。
- 梳理 `MainActivity.getDirectories`、`MediaActivity.getMedia`、`getPhotoProfileMedia`、`GetMediaAsynctask` 及分类扫描的入口、重试、通知与取消点；先识别**真正重复**的工作，再合并/取消/延迟重复请求。
- 对同一个来源范围保留唯一**可提交的最新请求**，确保每次实际执行的刷新有 COMPLETE/PARTIAL/FAILED/TIMED_OUT/CANCELLED 或访问受限等明确结局，不让进度指示无限存在。
- 不把 MediaStore 没有索引到 `.nomedia` 内容误判为目录空或扫描完成；不以部分读取推断文件已删除。
- 只有必要时增加**轻量协调器或纯函数策略**；优先复用现有 `DirectoryScanEpoch`、`GalleryScanTerminalGate`、`MediaChangeRetryGate` 等，避免另造平行的请求状态系统。

### S2：排序和媒体目录交接（保留排序算法）

- 继续使用原有 `MediaFetcher.sortMedia`、分组规则、搜索/筛选、目录/收藏/配置来源语义。
- 收敛缓存预览、索引、文件补扫多阶段中重复的全量排序与列表发布。确认同一 scope / sorting / content revision 对应的最终序列，只在集合或排序条件真正改变时更新。
- 随机排序要在一次浏览会话内保持当前顺序；不能因一次缓存或分阶段刷新突然全体重排。
- 全屏浏览使用与来源列表一致的身份/顺序与最新授权，不把五张邻近预览/分段窗口当成目录 END；不推翻当前 fix 的全屏渐进式设计。

### S3：显示提交、滚动位置与动画稳定性（保留 Adapter）

- 继续复用 `MediaAdapter`、`DirectoryAdapter` 现有稳定 ID、DiffUtil、异步差分、滚动锚点和快速滚动条。
- 收敛多次中间快照的 UI 提交：无变化不提交；元数据变化做精确局部更新；同一轮刷新尽量避免整体 adapter=null、整页动画或重复布局。
- 滚动、拖动、选中模式进行中优先保留用户位置，必要的新快照在安全时点提交。对位置/临时扫描字段和真正可见内容区分比较，以避免重复缩略图绑定和闪烁。
- 不改变 OxygenOS 风格的动画规范、控件尺寸、Ripple、图标和菜单；目标是去除**错误**动画，而非改 UI 设计。

## 4. 明确不做的事

- **不重建** Room 数据库、Fossify 原有文件操作、缩略图引擎/图片解码、视频播放器、编辑器或权限底层。
- **不改动** 自定义顶栏/底栏的视觉与配置，照片配置的模型和序列化、收藏关系、备份格式以及用户设置的存储语义。
- 不引入新的持久化索引，除非后续采样证明必要，且必须先单独论证。
- 不合并 `main`、不重置历史提交、不创建另一个 fix 分支；后续新增需求按单独审批/任务边界处理。
- 不为“性能”绕过受保护目录、收藏、照片配置的授权检查；不要求清除应用数据、不执行破坏性 Room 迁移。
- 不预先大规模改写 `ViewPagerActivity`、`MediaFetcher`、`MainActivity`、`MediaActivity`；只修改经源码证据或可复现测试确认的必要调用点。

## 5. 验收条件（必须以数据和测试验证，不能凭感觉填写“通过”）

| ID | 功能验收 | 失败证据 / 观察指标 |
|---|---|---|
| A01 | 普通与 `.nomedia` 文件夹新增/删除后，主页卡片数量、文件夹内部列表和配置来源按当前授权一致 | 文件系统实数、卡片计数、三视图数、扫描状态 |
| A02 | 重复刷新/切换页面后最终有效任务一定结束，旧请求不覆盖新结果 | requestId/epoch/terminal、loading indicator、取消与队列记录 |
| A03 | 刷新未改变媒体顺序时滚动位置稳定，普通点击和高速滑动无大面积“扑克牌式”闪动 | 顶部 path+offset、adapter 重建/commit、bind/diff、录屏帧 |
| A04 | 排序、分组、搜索、随机顺序、自定义配置跨目录去重正确 | 同一 scope 的排序快照、数量和身份 |
| A05 | 从普通目录、收藏和配置打开全屏，连续向前/向后滑动超过五张；局部边界不假报终点 | currentPath、catalog revision、UNKNOWN/HAS_MORE/END、窗口扩展 |
| A06 | 保护目录/收藏/配置在鉴权失效或切换配置后，不再发布旧数据 | 权限变化测试、缓存/全屏/预览访问记录 |
| A07 | 配置、收藏关系、主题、顶栏/底栏、备份导出导入和旧版升级均未回归 | 相关单元测试 + 必要真机回归 |
| A08 | 与修复前同场景相比，重复扫描次数、UI 不必要提交与滑动跳跃明显减少；不凭空给定性能目标 | baseline/after 的同设备、同数据量 p50/p95 对照 |
