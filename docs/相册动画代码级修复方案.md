# 相册动画代码级修复方案

## 范围与代码基线

录屏为 54.37 秒、576 × 1280、30 FPS。我抽查了 0.4 秒与 30.7–31.4 秒画面：前者能看到截图悬在黑底中央，后者能看到 OPWeather 封面独自处于大片白色页面中，随后页面内容才铺开。这与用户提供的时间轴结论一致。再对照工作区 `Gallery/app` 当前源码，发现当前版本已经有相册封面和照片的 Android shared-element 转场，关键入口分别在 `MainActivity.albumTransitionOptions()`、`MediaActivity.launchPhotoViewerWithSharedElement()` 和 `ViewPagerActivity.finish()`。因此建议修的是转场就绪、背景协同、目标失效时的回退和页面恢复，而不是再叠加一套独立缩放动画。

`change-source/app` 只包含部分 Activity/Helper 文件，不包含完整的适配器、Fragment 和布局；实施时应以完整的 `Gallery/app` 为准，再按项目实际发布流程同步必要变更。

## 当前实现与录屏问题的代码对应

| 录屏症状 | 当前代码位置 | 需要补齐的行为 |
| --- | --- | --- |
| 黑底上图片独立缩放 | `MediaActivity.launchPhotoViewerWithSharedElement()` 仅在缩略图仍绑定、已加载时启动共享元素；条件不满足会直接普通 `startActivity()`。Viewer 主题及 `onCreate()` 将窗口/根/分页背景设为黑色。 | 共享元素不可用时，使用短淡入淡出，不让普通 Activity 动画表现成黑底小图缩放；共享元素可用时，让黑色画布随图片变形同步显现。 |
| 当前图片回不到原位 | `ViewPagerActivity.finish()` 已通过 `getCurrentPath()` 取关闭时的照片，`MediaActivity.onActivityReenter()` 按 path 找回对应网格项。 | 保留这条按 path 回归的设计；目标不在可见区或已被移除时，不要强行映射到错误缩略图。 |
| 文件夹封面独自飞行、网格迟到 | `MainActivity.albumTransitionOptions()` 只指定封面为共享元素；`MediaActivity.maybeReleaseAlbumTransition()` 等待网格和可见缩略图就绪，最长等 `AlbumPageTransition.READY_TIMEOUT_MS`。 | 封面只做轻量位置过渡；内容页先稳定绘制，其他内容以短淡入出现。超时走明确的淡入淡出回退。 |
| 返回时卡片压住邻居或消失 | `MediaActivity.finish()` 与 `MainActivity` 的退出共享元素映射按封面路径找目标。当前主页目标检查 attached/visible/drawable，但还没有验证该 drawable 属于当前绑定请求。 | 返回映射前核对 adapter position、文件夹 path 和缩略图 request/load key；校验失败就淡出文件夹页。 |
| Camera 文件夹长时间白屏 | 文件夹页的共享元素入场被 `maybeReleaseAlbumTransition()` 和 1.2 秒超时控制；普通媒体扫描/首批缩略图请求在 `getMedia()`、`setupAdapter()` 链路中进行。 | 让页面壳和首批可见缩略图先出现，慢扫描只显示局部进度；不要把“所有首屏图已解码”作为显示整个页面的门槛。 |
| 左右滑动与开合冲突 | 普通 `DefaultPageTransformer` 只清理 translation/alpha；Fragment 在 `isMediaTransitionRunning()` 时已拦截部分手势。 | 保持分页只做水平移动；在共享转场期间统一拦截触摸/返回，完成后再开放；相邻图预加载，避免文字截图在交接帧同时显示两页。 |

## P0：照片缩略图 ↔ 全屏 Viewer

### 修改点

1. **`Gallery/app/src/main/kotlin/org/fossify/gallery/activities/MediaActivity.kt`**
   - 保留 `launchPhotoViewerWithSharedElement()` 对 holder、position、path、`thumbnail_request_key` 与 `thumbnail_loaded_key` 的一致性校验，以及 `setIsRecyclable(false)` 的 source lease。
   - 将“共享元素启动失败”从普通 `startActivity(intent)` 改成一个统一的 `launchViewerWithoutSharedElement()`：设置 `PhotoViewerTransition.EXTRA_PATH` 不存在，关闭共享元素映射，并使用约 120–160 ms 的淡入淡出/无窗口缩放进入。source lease 失败时立即释放，避免黑底独立小图的系统默认动画。
   - 把 `onActivityReenter()` 的等待逻辑抽成可复用函数：只有当目标 path 仍在 adapter、holder 绑定到同一个 path、图片请求 key 已完成时才启动返回共享转场；否则清理 pending path，并使用淡出回退。若目标在屏幕外，先定位目标并等待下一次 pre-draw；超过 deadline 不再硬映射。

2. **`Gallery/app/src/main/kotlin/org/fossify/gallery/activities/ViewPagerActivity.kt`**
   - 在 `onCreate()` 的 `setEnterSharedElementCallback` 中继续按 `photoSharedElementPath` 绑定当前照片的 `sharedElementViewFor(path)`；只有 `imageRendered(path)` 已确认 drawable ready 才释放 `postponeEnterTransition()`。
   - 将当前 `animateSharedChrome()` 扩展为同步控制一个 viewer 背景 scrim：进场时背景从来源页面颜色平滑变为黑色，照片接近最终位置时工具栏淡入；返回时 scrim 反向淡出，照片缩小时网格同时可见。Scrim 应放在 `activity_medium.xml` 的照片画布下层、工具栏之上，不能遮挡共享图片。
   - 不对共享图片本身加第二个 scale/alpha 动画；`OxygenClassicActivityMotion.mediaTransition()` 的 `ChangeBounds + ChangeImageTransform` 作为唯一照片几何转场。
   - 保持 `finish()` 的 `getCurrentPath()` 语义。A 打开后切到 D 再返回，目标必须是 D。若 `getCurrentSharedElementView(D)` 因 D 不可见、缩放中、旋转中或图片类型不适合而返回 null，执行短淡出，不能缩到屏幕中心后消失。
   - 在 transition running 标志有效期间拦截 ViewPager 横向触摸、双击缩放和系统返回竞争；当前 Fragment 的手势已检查 `isMediaTransitionRunning()`，需要把检查覆盖到所有入口，并在 transition 完成/取消/超时三种分支都复位。

3. **`Gallery/app/src/main/kotlin/org/fossify/gallery/fragments/PhotoFragment.kt` / `MediaSharedSurface.kt`**
   - 继续共享已显示图片的像素与当前显示 bounds，不把黑色 letterbox 或 viewer 全屏容器作为共享元素。
   - 对长截图和文字截图沿用同一 drawable，开合过程禁止切换低清占位图或重新绑定另一张图；在 shared surface 清理后再恢复高分辨率/缩放图层。
   - 旋转、放大、GIF、SVG/RAW 等不支持安全几何共享的情况走淡出回退，不尝试用不同坐标系拼接 bounds。

### 转场状态建议

把散落的布尔值收敛为 `PhotoTransitionState`（可放 `helpers/PhotoViewerTransition.kt`）：`Idle → WaitingForSource → Entering → Browsing → Returning → Idle`，失败/取消统一回 `Idle`。每次新请求递增 generation，异步图片回调和 timeout 只有 generation 匹配时才能释放动画，防止快速打开、滑动、返回时旧回调改变新页面。

## P1：主页 ↔ 文件夹页面

### 修改点

1. **`Gallery/app/src/main/kotlin/org/fossify/gallery/activities/MainActivity.kt`**
   - 在 `albumTransitionOptions()` 创建转场时记录 `pendingAlbumReturnPath` 和主页 RecyclerView 的滚动锚点（path + offset）。
   - 在退出映射中，`findDirectoryThumbnail(path)` 除检查 holder position 外，还要确认 holder 当前绑定的目录 path 与请求 path 一致，且 `thumbnail_loaded_key == thumbnail_request_key`。`DirectoryAdapter` 绑定时给封面图设置 request/load key 或 holder path tag。
   - 找不到完全匹配且已加载的封面时，从 sharedElements 移除该元素并淡出文件夹页；不要把过期 holder 的 drawable 作为回程目标。
   - MainActivity 在文件夹返回时保留已有列表和滚动位置；仅在布局确实变更时恢复锚点，避免返回动画结束后整页突然重新布局。

2. **`Gallery/app/src/main/kotlin/org/fossify/gallery/activities/MediaActivity.kt`**
   - `configureAlbumPageTransition()` 保持共享元素只代表文件夹封面，不扩展成整页卡片变形。
   - `maybeReleaseAlbumTransition()` 改为“页面可绘制就进入”：RecyclerView 完成首帧布局、目标封面已加载或明确不可用即可启动。其他首屏缩略图允许在稳定网格上逐张填充，不要求全部图片解码后才进场。
   - 将 1.2 秒 timeout 改成短等待（建议 300–500 ms）后走 fade-through；不要让用户看到空白页面等待 timeout。首屏没有媒体时直接展示空状态，不保留空白容器。
   - 仅对目标封面执行 220–240 ms `ChangeBounds + ChangeImageTransform`；新页面网格用 100–140 ms alpha 建立。限制封面自身位移/尺寸变化，不缩放整个文件夹页面。

3. **`Gallery/app/src/main/kotlin/org/fossify/gallery/helpers/AlbumPageTransition.kt`**
   - 将 `DURATION_MS` 从当前 300 ms 调整到 220–240 ms；把 `FADE_DURATION_MS` 真正接入页面内容显隐，不再保留未使用的常量。
   - 增加共享元素失效回退时长与短 timeout 常量，并保持系统关闭动画时完全跳过转场。

## P2：白屏、加载与网格稳定性

1. **`MediaActivity.getMedia()` / `setupAdapter()` / `MediaAdapter.setupThumbnail()`**
   - 保持 RecyclerView 和已有 item 在后台扫描期间可见；刷新时对已有列表做 diff 更新，不先 `adapter = null` 再整页重建。
   - 转场期间暂停目录排序/网格重置造成的 item 移动；扫描结果仍可在后台准备，转场完成后通过现有 diff 提交。
   - `thumbnail_loaded_key` 只用于该请求成功后的可见状态，不应在同一批更新中让整行缩略图同步播放淡入；普通 thumbnail crossfade 在共享转场目标上保持关闭（当前已用 `crossFadeDuration = 0`，保留此点）。

2. **加载 UI**
   - 用现有 `mediaHeaderProgress` 显示顶栏细进度，不覆盖内容网格的整屏 loading spinner。
   - Camera 文件夹首帧：先显示 toolbar、稳定背景和已缓存/已解码缩略图；扫描慢时只显示进度条。没有任何内容且确实处于加载时显示轻量占位，不让空白白屏持续两秒。

## P3：左右翻页与快速连续操作

- 普通翻页继续使用 `ViewPager` 默认水平滑动，不加卡片缩放、旋转或额外透明度；`FadePageTransformer` 仅保留给用户选择的幻灯片淡入效果。
- 打开/返回共享转场期间不接受新的左右分页手势；到 `finishMediaTransition()` 后开放。用户在动画进行中发出的系统返回应取消/收束当前转场，不并行启动另一套位置动画。
- 对页面切换使用同一水平距离、方向和 easing；图片的适配比例在每个页面内部稳定处理，不联动移动工具栏、系统栏或整个黑色画布。
- 文字截图交接用相邻页预加载和 pager 页面离屏缓存解决；不要通过两页同时降低 alpha 来制造淡化，以免出现文字叠影。

## 推荐落地顺序

1. 先补照片开合的确定性回退、背景 scrim 同步、当前照片 path 回归与手势互斥。
2. 修文件夹封面目标校验、页面首帧 readiness、单图文件夹及超时回退。
3. 修主页返回滚动锚点和目录 holder 绑定校验。
4. 最后收紧 Camera 首屏加载与网格增量刷新，再调整时长和曲线。

## 代码级验收条件

- 打开/关闭照片时，照片从可见缩略图 bounds 出发并回到关闭时当前照片；没有有效 target 时只淡出，不出现黑底小图缩放。
- 照片 bounds 动画、viewer 背景 scrim、toolbar 显隐同一时段启动；工具栏不先于照片抢显。
- A→D 后返回定位 D；D 不在列表/不可共享时回退清楚，无错图、闪黑或悬浮小图。
- 文件夹封面只在自身 bounds 内过渡，其他卡片不被盖住；单图文件夹首帧位置固定。
- 返回主页后，封面回到原 path 卡片，其他卡片和列表滚动锚点稳定；holder 失效时走 fade-through。
- Camera 文件夹已有内容时不出现整屏白屏；慢扫描期间已有缩略图不消失、不整行重播入场。
- 普通左右翻页只有水平移动；进场/回程动画未结束时不会与滑动、缩放、返回并发争抢。

录屏为 30 FPS，因此本方案把可见的黑屏、白屏、错位、内容跳变作为交互验收项；帧耗时和 GPU 掉帧需要单独采集，不能从这段视频单独下结论。
