## 结论摘要

- 当前 HEAD 下没有复现需要改动生产转场代码的缺陷。共享封面、照片进入/返回身份、离屏返回、下滑取消/确认等现有路径在 Pixel_4 API 29 软件渲染 AVD 上通过。
- 本阶段为收藏照片网格补上“打开、翻页、系统 Back 返回当前缩略图”的设备回归；实际缩略图身份同时核对 adapter path、`media_bound_path`、request key 和 loaded key。
- `PhotoViewerInteractiveGestureTest` 的既有 5 项在当前 HEAD 为 5/5；新收藏照片用例在隔离运行时为 1/1。两次采集并行运行时曾有一次邻页身份失败，见下方测试设施记录。
- AVD 的原生 `screenrecord` 返回 `Encoder failed (err=-38)`；Android Studio 的 Running Devices 面板也不能镜像由命令行启动的 AVD。ADB 截屏替代方式约 0.6 秒一张，无法逐帧判定 120ms 转场是否闪帧。已取得的屏幕截图和几何采样不构成连续录屏，也不证明无空帧。
- 没有 Pixel 8 Pro 或其他硬件加速 arm64 设备。AVD 60Hz、软件渲染的 `gfxinfo` 在手势回归中为 56/57 帧 deadline missed，中位 40ms、P90 53ms、P99 109ms；该结果包含测试注入负载，不是硬件性能结论，也没有修复前对照数据。

## 代码与控制权审计

## 本阶段新增回归

新增 `favoritePhotoViewerReturnsToTheLastSwipedThumbnailOnDevice()`：以 3 张临时合成图片构造真实收藏集合，打开收藏 Viewer，核对 Viewer 当前身份，横滑到其真实分页目录中的相邻照片，触发系统 Back，再核对返回 ImageView 的 `media_bound_path`、request/loaded key 和 Activity 可见性。清理时移除合成收藏记录及 MediaStore 图片。

上一轮新用例最初用源 adapter 排序预测 Viewer 邻页，失败后确认收藏 Viewer 自有分页目录顺序才是正确断言基准；测试已据 Viewer 的 `mMediaFiles` 核对，并保留 source 与 viewer 的照片 identity set 相等断言。

## 可见画面与性能范围

- 设备测试在打开 Viewer 后采集实际屏幕截图，记录下滑三个中间手势帧，并在返回网格采集截图；`ViewPagerActivity` 另记录 shared element 进度与边界，现有断言要求多个中间帧、边界尺寸发生变化、进度单调。可查看 `/private/tmp/Gallery-phase3-validation/phase3-opened-viewer.png`、`phase3-drag-2.png`、`phase3-drag-3.png`、`phase3-returned-grid.png`。
- `adb shell screenrecord --time-limit 180` 立即返回 `Encoder failed (err=-38)`，设备文件为0字节；未将空视频作为证据。Android Studio 的 Running Devices 面板提示它不能镜像当前 CLI 启动的 AVD。尝试的 `adb exec-out screencap -p` 采集到53张图/31.452秒，实际平均约0.59秒一张，contact sheet 在 `favorite-screen-samples/contact-sheet.png`。该采样能显示合成收藏页与 Viewer 状态，但远慢于120ms动画，不能证明转场无闪帧或图片无跳位。
- 在不并行屏幕采集的手势测试中，`gfxinfo` 记录57帧，其中56帧 deadline missed；50th 40ms、90th 53ms、95th 69ms、99th 109ms，明显高于此60Hz AVD的16.7ms预算。此数据只反映软件渲染仿真设备上的合成图片与 Android instrumentation 注入负载，没有同设备修复前数据；不能宣称模拟器或真机达到帧性能目标。
- 无 Pixel 8 Pro 或其他硬件加速 arm64 真机，故真机刷新率下的帧时间、Profiler 对照和持续录屏尚未验收。慢缩略图、旋转/前后台恢复、系统关闭动画、长时间快速重入未增加新的实机回归；相关代码的取消与清理做了静态路径复核。
