# 阶段 2 真机问题修复

起点为 `6ba218823fe464fcd701454408ab913fa3fb0f2a`，本地与远端 `perf/home-gallery-sorting` 一致，工作区干净。原设备为 Pixel 8 Pro / API 36，附件含 17 次 Session。约 00:53.4–00:55.3，松手前 A 留白，B 同时出现在网格和拖拽画面。另一次返回 `request=8` 在已提交列表查不到 B，约 1.2 秒后降级，完整 3,080 项列表随后发布。

## 手指仍按住时的所有权

- Viewer 准备好当前 renderer 的代理后，由同一交互 operation 请求 Grid 显示拖拽预览。Session 通过弱引用通知所属 Grid，UI 与清理闭包仍由 Grid 自己持有。
- 对入场时保存的 path、视图、drawable 和加载键重新核对。匹配的 A 若仍受旧出场隐藏影响，恢复 launch 时的 alpha。仅当 B 仍是已提交 Adapter 内已加载、位置和可见范围都有效的 Holder 时，才暂时隐藏其缩略图。
- `GRID_PREVIEW` 租约持有被遮住的 B。预绘制发现位置、drawable、绑定、作用域或可见区域变化便释放。Adapter 在翻绑或回收前还原自己将接管的视图。取消、回弹完成、终态、授权失效和销毁时均撤销遮蔽。
- 松手沿用该交互 operation。目标校验只允许本次操作实际持有的 alpha 遮蔽，通过映射校验后在平台回调中恢复 B 的原透明度，交由 Android 完成共享元素捕获。普通透明目标继续拒绝。
- 新事件 `grid_interactive_preview` 记录少量边界决策，沿用 Session、operation 和 generation 关联。运行时路径、媒体内容和私有令牌保持在诊断之外。

## 部分列表返回

- 若 B 已提交，继续等待有效的 Holder、布局和 drawable。若 B 尚未提交，立即解除平台窗口等待，走现有淡出路径。没有候选时不取得 Holder 或 Adapter hold。
- 淡出后的回位按 B 的身份等待下一次合法提交。位置出现后仍有原布局等待上限。用户开始滚动、新导航、作用域变化、授权失效、最终列表不含 B 或窗口销毁时取消待回位。
- 受控用例在修复前观察到 Grid 仍处于延期状态。测试同时覆盖了超出原窗口超时后才提交 B，并检查用户快滚后晚到的提交不会接管位置。

扫描、缓存、缩略图优先级、手势曲线和几何保持原路径。快滚出现多行灰白占位继续单列。
