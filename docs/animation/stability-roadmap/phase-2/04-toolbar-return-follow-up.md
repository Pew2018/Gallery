## 真机证据

Pixel 8 Pro / API 36 录像约 00:04 和 00:10 可见 Viewer 的文件名及按钮叠在 Grid 的 WeiXin 顶栏上，持续到手势继续移动。约 01:04.6、01:08.3 和 01:10.7，视频回程画面覆盖 Grid 顶栏的一部分，随后落回对应格子。

对应会话 `request=26/28/30` 的 `viewer_transition_end` 中，Viewer 代理的顶部为屏幕 y=59–60，Grid 目标实际可见顶部为 y=319。三个会话均在 8–9 ms 后收到 Grid 捕获起始回调。这个差值解释了部分首行交接前的遮挡。代理完整边界仍用于原来的位置和裁切矩阵。诊断的 draw/frame commit 无法证明屏幕实际呈现。

## 调用关系与资源

| 阶段 | 修复前 | 修复后 |
| --- | --- | --- |
| 手指按住或取消回弹 | Viewer 顶栏跟随 scrim 淡出时，Grid 顶栏已经透出 | Grid 在当前 operation 下报告实际可见的顶栏边界。存在可用顶栏且 scrim 开始露出后，Viewer 顶栏 alpha 置零。 |
| 普通返回或手势提交 | 回程继续从屏幕上的 alpha 淡出，Viewer 代理按原完整目标边界移动 | 露出 Grid 时沿用同一顶栏交接。视频回程代理在预绘制中按 Grid 顶栏底边限制绘制，过渡捕获继续使用完整边界。 |
| 取消、降级、销毁 | 原有 Session 终态及租约清理 | 手势取消恢复 `CHROME` 保存的 Viewer alpha。视频预绘制和原 clip 由 `RETURN_TOOLBAR_CLIP` 租约释放，随后清除代理。旧 token 无法查询新 Grid 的边界。 |

Grid 顶栏不可用时按现有 Viewer alpha 路径处理。Session 状态转换、系统栏进度、底栏、scrim 曲线以及共享目标身份校验沿用原有路径。

## 测试与本地构建

- 开工基线用同一测试 APK 在 API 29 复现两项断言失败。手指按住时 Viewer 顶栏 alpha 仍为 0.4。半可见首行的原生回程也采到了原始代理越过顶栏且未应用裁切的绘制帧。
- JVM 增加三项用例，覆盖按住时的顶栏交接、取消时恢复原 alpha、普通返回的首个露出帧，以及视频代理随当前位置和缩放计算 clip、恢复原 clip、保持目标端点。
- 设备用例从照片打开 Viewer，切到视频，向半可见首行提交返回。它要求采到原始代理边界越过顶栏的原生绘制帧，并逐帧检查 clip。用例在冷启动的照片入场发生已知降级时，最多重新准备三次。到达原生回程后直接判定，无回程重试。
- JDK 21 已构建 FOSS Debug、AndroidTest 与 ARM64 Release。Lint 延用基线 14 个错误、802 个警告、2 个提示，按文件、级别和规则描述归一化比较新增 0、移除 0。

开工基线重新构建并执行完整 JVM 测试，1,251 项通过。修复后 1,254 项通过。两版均为 0 失败、0 跳过。

- API 29 和 API 37 均通过半可见首行视频回程、照片和视频切换后的按住拖拽、取消与提交。两台模拟器的半可见场景都观察到原始代理边界穿过顶栏，裁切断言通过。
- API 37 连续 50 次往返全部清理。39 次走共享返回，11 次走既有降级。收藏中切换到另一张照片后返回通过。
- API 37 的既有部分列表快滚断言在批量运行两次失败，记录 offset=3071、range=2806。使用同一模拟器隔离复测及按收藏返回、部分列表快滚的相同顺序复测时，开工和修复版本均通过。该断言测量的是部分列表中的快滚位置。
- API 29 的既有三种比例视频用例在开工和修复版本均通过颜色与比例检查，随后在同一个触摸注入断言失败。
