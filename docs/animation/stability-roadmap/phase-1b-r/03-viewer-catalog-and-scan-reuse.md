# Viewer 目录复用

旧 `openOrdinaryViewer` 的 `viewer_catalog_miss` 表示没有独立目录票据，Grid order 和局部窗口由其他存储器传递。旧 complete catalog 的检查点拒绝所有文件访问模式，允许的目录条目必须有 MediaStore ID，且一次读取即消耗该目录。任务说明中的五次 miss 符合这条路径。原始事件缺失，无法对每次拒绝原因独立归因。`startFolderViewer` 在鉴权后先显示选中项，校验邻近候选，然后触发独立目录扫描，已提交的 Grid 全量候选只提供顺序和可扩展局部窗。缺少完整范围、权限和扫描期间版本证据时，保留真实扫描是必要的。

`GetMediaAsynctask` 复用阶段 1B 普通物理目录已有的 scan-start FileObserver。只有稳定的非随机、普通公开目录请求，COMPLETE 的 direct 枚举、当前访问权限以及扫描前后匹配的检查点才可准备目录。检查点包括规范目录、MediaStore 卷版本及代际、目录 mtime、内容修订、配置、读权限模式、授权及保护规则。目录中仍有未索引的文件时，只有已证明的所有文件访问直读可接受无 MediaStore ID 的行。区域保护、SAF 受限目录、局部照片授权、`.nomedia`、虚拟目录和旧未完成请求继续走各自的权威读取。

`MediaActivity` 只为当前请求已完整提交的普通文件夹选择目录，并维持原 Grid pause/resume 的扫描复用。目录缓存最多一份、最多 50,000 行，由内存回调清理，每次打开复制 Viewer 可变媒体对象，不和来源或其他 Viewer 共享可变模型。读取与最终发布前复验检查点，观察器变化或停止即失效。命中后仍执行现有 Viewer 文件夹会话、搜索、过滤、逐路径可读和授权校验，采用已匹配的网格顺序。逐文件存在性和权限检验有成本，独立目录枚举、媒体 DB/MediaStore 查询和逐文件媒体元数据读取由合格命中路径省去。

局部窗先授权显示。完整目录缺失、变更或验证失败时继续扩窗和后台扫描，直至有 COMPLETE 证据。成功采用完整目录后，Viewer 监听这一物理目录，合并外部写入事件，真实变化时打开权威查询。回前台、使用新目录和感知文件变化时复查访问，已有删除路径仍触发正常失效。保护目录鉴权、回位身份和临时授权流程沿用现有路径。

API 37 对照中，1B 的五个 Viewer worker summary 均将调用方已有的 VIEWER 原因清洗为 UNKNOWN。通过独立 summary ID、单次来源加载和五次完成的 fallback 对齐。1B-R 将 VIEWER 加入诊断枚举允许值。
