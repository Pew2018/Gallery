## 改动与受控失败

真实 RecyclerView 单测在旧版以 3,080 项启动拇指滚动，跳到短暂停留的中间位置再反向。旧版为瞬态 Holder 创建了实际 Glide `SingleRequest`，触发失败。修复版在连续拇指移动时合并加载启动，只为交互停止后仍可见并保持当前绑定的 Holder 启动请求。滑块停留 48 ms 可以加载当时视口，松手后在下一帧重新检查最终位置。长时间手势无需等待松手才能看到缩略图。现有已加载 Drawable 继续按同键复用，换绑和回收继续核对 token 并取消旧请求。单测验证中间位置无提交、落点运行、停顿可加载、松手不重复提交。

API 29 的实际筛选对话框用例在旧 APK 观察到 `grid.adapter == null`。修复后，符合完整直读条件的普通物理文件夹将当前已验证集合投影到新筛选，沿用 Adapter 和稳定 ID。保留顺序与仍有成员的分组，复用现存的滚动锚点逻辑。投影只交付新筛选允许的现有条目，并标记为部分。原来源读取对权限、保护、可见性和授权的检查继续生效。新扫描仍发现扩大筛选后才可见的媒体并发布权威完整列表。受限路径、搜索、配置和不确定的访问仍走原有刷新流程。

新增滑块开始与释放、视口准入、筛选确认与投影完成的事件。事件沿用诊断的默认关闭、限频存储和自动过期。实际首帧及白块面积由录屏验证。

## 下一次真机验收

在同一 Pixel 8 Pro 和目录上录三轮冷区、回跳、立即反向，一次 3,080→288 的筛选，以及五次 Viewer 往返。录屏与日志同次采集。建议门禁为松手或确认后，半屏以上空白不得持续超过 1 秒。同时要求无错图、无无因扫描、无回位身份错误。当前修复版的真机数据仍为 NOT MEASURED。

## 模拟器对照

API 29 定向用例的 1,500、3,080、5,000、10,023 项共 40 个冷区或热回跳视口均在 3 秒内恢复。测试核对媒体路径、绑定 token 和合成红蓝像素。早期同操作 A/B 各五个 3,080 项窗口，阶段 1B-R 松手后冷/热 p50 为 62/50 ms，新策略为 77/76 ms。旧版在松手前已提交瞬态请求，这组松手后的数据保留为恢复测量，瞬态请求是否提交由独立受控失败验证。

使用 2,792 张图片、288 段小视频的实际筛选对话框用例，旧 APK 在确认后拆除 Adapter。新版约 115 ms 投影到 288 项，约 1,270 ms 等到全部可见缩略图就绪，并通过权威扫描和放宽筛选恢复 3,080 项。首屏全部就绪时间与 Pixel 真机半屏空白的持续时间是不同的验收指标。
