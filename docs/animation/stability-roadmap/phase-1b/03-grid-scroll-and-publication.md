# 网格滚动与发布

`MediaAdapter.submitPendingUpdate` 每次仅保留一个排队快照和一个已开始的 Diff。后台 Diff 结果返回后带上原代际、旧列表计数与完成时间。RecyclerView 正在计算布局时通过下一动画帧继续处理原 Diff。手指拖动、快滚滑块和有效 Viewer 返回租约继续由各自的状态事件解除。允许普通惯性滚动在布局外提交保留锚点的扫描更新，其他即时排序和搜索继续遵循原有约束。

同一提交基线只应用一次 Diff，新代际直接替换已暂缓版本。惯性滚动中的提交按可见媒体路径和装饰后 offset 设置一次下次布局锚点。用户后续手势无需消费较早的 pre-draw 位置修正。合理的同媒体同 key 复绑保留 drawable。异步完成回调匹配实际请求 token 实例，覆盖 A→B→A 复用。原本的事件保留，限频 drawable 事件增加测量宽高、可见宽高和滚动/布局状态。

受控 1,454→3,080 场景执行真实 RecyclerView、Adapter 与手动 Diff executor。旧版布局解除后继续等待，修复版在两个虚拟帧之内提交同一 Diff。断言包括无重复计算、Adapter 只递增一次、媒体身份、锚点 offset、缩略图高度与已加载 drawable。文件名条、裁切、解码和过场参数保留现有行为。修复后的真机冷启动和滚动帧证据待补采。
